# Zakaz BB — ресторанный планшет самообслуживания

**Zakaz BB** — kiosk-first сервис для заказа блюд за столом. Гость выбирает блюда на планшете, добавляет соусы и дополнения, подтверждает состав и следит за состоянием заказа. Меню, стоп-лист, рекламные баннеры и настройки конкретного планшета управляются из защищённой админ-панели.

Продакшен: [заказ.звяк.рф](https://xn--80aatcn.xn--b1ajk7f.xn--p1ai)

## Что уже умеет продукт

- Приветственный экран с рекламными и меню-баннерами, вызовом официанта и привязкой к столу.
- Каталог блюд: категории, поиск, подробные карточки, КБЖУ, соусы, дополнения и блок «Идеально с этим блюдом».
- Корзина, финальная проверка, создание заказа на сервере и экран статуса приготовления.
- Несколько активных заказов с быстрым переходом из раздела «Заказ».
- Стоп-лист с визуальным штампом на карточках блюд.
- Запрос официанта с планшета.
- Автоматическая защита гостевой сессии: предупреждение о бездействии показывается только во время выбора и не прерывает главный экран или ожидание уже отправленного заказа.
- Админ-панель для стола и терминала, меню, стоп-листа, баннеров, аудита и проверки качества данных.
- Android APK в полноэкранном режиме, локальные изображения в приложении и OTA-обновления интерфейса без повторной установки APK.

## Для презентации

Сервис рассчитан на планшет за конкретным столом. После первой настройки терминал запоминает свой идентификатор, а администратор задаёт для него номер стола. Поэтому гостю не нужно каждый раз выбирать стол — заказ сразу связывается с нужной посадкой.

Интерфейс намеренно построен вокруг одного сценария: **заказать → проверить → дождаться готовности**. Навигация и заголовки остаются на месте, а прокручиваются только длинные списки: блюда, состав заказа или история заказов.

## Как войти в админ-панель

1. Откройте главный экран приложения.
2. Быстро нажмите **6 раз на изображение маскота справа**.
3. Введите служебный пароль.

Пароль не хранится в репозитории, браузере или APK. На сервере хранится только его SHA-256-хеш в переменной `ADMIN_PASSWORD_HASH`. После входа откроется раздел управления терминалом.

В админ-панели можно:

- назначить номер стола, название и тайм-аут конкретному планшету;
- менять названия, цены, описания, КБЖУ, фото, соусы и рекомендации блюд;
- добавлять и снимать позиции со стоп-листа;
- управлять ресторанными промо-баннерами;
- просматривать журнал служебных изменений.

## Технологии

| Зона | Решение |
| --- | --- |
| Клиент | Vanilla TypeScript, Vite, HTML/CSS, touch-first адаптивная вёрстка |
| Состояние и маршруты | Собственный store и hash-router без тяжёлого UI-фреймворка |
| Сервер | Node.js HTTP API, PostgreSQL (`pg`) |
| Изображения и offline | Локальные WebP/PNG-ассеты, service worker, PWA manifest |
| Android | Capacitor 8, нативный fullscreen, Lock Task для Device Owner |
| Обновления | GitHub Actions + Capgo Capacitor Updater (OTA) |
| Развёртывание | Nginx, systemd, GitHub Actions |

## Архитектура

```text
Планшет / браузер
  └─ Vite SPA → REST API → PostgreSQL
       ├─ меню, стоп-лист, терминал, промо
       ├─ заказы и запросы официанта
       └─ служебная авторизация и аудит

GitHub Actions → production web bundle + OTA-архив → Android-приложение
```

Клиент получает актуальные данные через `/api/v1/bootstrap`. Сервер — источник правды: перед сохранением заказа он повторно проверяет доступность позиций, количество, соусы, дополнения и итоговую сумму. Это не позволяет отправить устаревший или подменённый заказ.

## Локальный запуск

Требования: Node.js 22+ и PostgreSQL для API.

```bash
npm install
npm run dev
```

Проверка production-сборки:

```bash
npm run build
npm run preview
```

Для API создайте серверный `.env` по примеру [`.env.example`](.env.example):

```env
DATABASE_URL=postgres://user:password@host:5432/database
TOKEN_SECRET=replace-with-a-long-random-value
ADMIN_PASSWORD_HASH=sha256-hash-of-admin-password
```

Секреты, пароли и ключи развёртывания не коммитятся. `menu.json` используется как исходный набор данных; в работающем продукте изменения меню вносятся через сервер и админ-панель.

## Android и kiosk-режим

APK собирается вручную из GitHub Actions **Build Android kiosk APK**. В него входят интерфейс и изображения меню, поэтому первый запуск не зависит от загрузки фотографий из сети.

При запуске приложение проверяет OTA-обновление. Обычные изменения интерфейса, сделанные в `main`, публикуются workflow **Publish kiosk OTA update** и приходят на планшет при следующем запуске с интернетом. Новая APK требуется только для нативных изменений: Capacitor-плагинов, разрешений, иконки, версии Android или kiosk-логики.

Полный запрет выхода из приложения возможен только при настройке планшета как **Device Owner** через MDM или Android provisioning. Без этого приложение остаётся полноэкранным; для теста можно использовать системное «Закрепление экрана». Детали: [docs/ANDROID_KIOSK.md](docs/ANDROID_KIOSK.md).

## Команды

```bash
npm run dev             # локальная разработка
npm run build           # TypeScript-проверка и production-сборка
npm run preview         # просмотр production-сборки
npm run sync:images     # загрузка и оптимизация исходных фото в WebP
npm run android:sync    # сборка web + синхронизация Capacitor Android
npm run android:debug   # debug APK локально
```

## Что намеренно оставлено следующим этапом

MVP уже готов для пилота в зале. Для полноценного промышленного запуска остаются внешние интеграции: приём оплаты, Keeper/KDS, реальный поток статусов кухни, рабочее место официанта, мониторинг и резервное копирование. Они не замоканы как «готовые» функции и должны подключаться отдельным этапом.
