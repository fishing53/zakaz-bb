# BrooklynBowl Kiosk — план до релиза

Актуально: 10 августа 2026.

## Уже работает

- Внешнее меню iiko поступает в серверный кеш и отображается в киоске.
- Столы iiko доступны для выбора гостем; закреплённый админом стол имеет приоритет.
- Стоп-лист iiko определяет доступность блюда в киоске.
- Заказ создаётся как заказ за столом iiko; статусы принимаются серверным webhook.
- Админка доступна по шести нажатиям на маскота и паролю.
- APK/OTA и серверный API развернуты отдельно.

## Критично до запуска в зале

- [ ] Провести реальный тест: планшет → стол iiko → печать/кухня → статусы в киоске.
- [ ] Проверить модификатор iiko: отображение, сумма, передача в заказ и печать на кухню.
- [ ] Сделать отправку заказа идемпотентной: повтор кнопки или сбой сети не создаёт дубль в iiko.
- [ ] Подключить `StopListUpdate` webhook после снятия лимита iiko; оставить редкую серверную сверку как резерв.
- [ ] Настроить резервное копирование PostgreSQL и мониторинг ошибок/доступности API.
- [ ] Добавить rate limit и временную блокировку для входа в админку.
- [ ] Проверить, что при удалении блюда из внешнего меню iiko оно архивируется в серверном кеше и исчезает из витрины.

## Сезонные меню и витрина

- [ ] Перевести локальное оформление с `productId` iiko на стабильный `SKU` (артикул iiko).
- [ ] Хранить по SKU: локальное фото, кадрирование, будущую анимацию, бейдж, «Идеально с» и баннерные привязки.
- [ ] Сделать безопасную загрузку локальных фото в админке вместо ручной ссылки.
- [ ] Перевести баннеры главной страницы на iiko SKU; не связывать их со старым локальным каталогом.
- [ ] Перед сменой сезонного меню: проверить уникальность SKU и сопоставление карточек витрины.

## Фундамент основного приложения на будущее

- [ ] Ввести единый `guest_session`: источник сессии (`tablet` / `QR`), стол, время начала и завершения. Это позволит одинаково обслуживать планшет и мобильный заказ.
- [ ] Ввести единую модель событий: `order_created`, `order_status_changed`, `waiter_called`, `waiter_accepted`. Киоск, QR-меню и APK официанта будут получать одни и те же события в реальном времени.
- [ ] Добавить `source` и `external_id` к заказам: отличать планшетный и QR-заказ, не создавать дубли при повторной отправке.
- [ ] Поддержать несколько открытых заказов одного стола и выбрать правило их объединения до подключения оплаты.
- [ ] Хранить историю статусов и действий по заказу, а не только текущий этап; это нужно для экрана официанта, поддержки и аналитики.
- [ ] Подготовить роли доступа: администратор, хостес, официант. Пароли/права не должны быть общими.
- [ ] Подготовить многоресторанность: `restaurant_id`/`organization_id` во всех новых сущностях, даже пока ресторан один.
- [ ] Сделать мобильную адаптивную витрину отдельно от планшетного режима для будущего QR-заказа.

## Официанты

- [ ] Для выделенных устройств официантов при необходимости включить kiosk/lock task; это повышает надёжность показа вызова.

- [ ] Добавить звук, push-уведомления и статусы «принят / в пути / выполнен».
- [ ] При необходимости синхронизировать ответственного сотрудника с iikoFront через отдельный локальный плагин.

- [ ] Экран управления сотрудниками и PIN-кодами в админке.

## QR-заказ с телефона

- [ ] Создать в админке QR-коды для каждого стола iiko.
- [ ] QR должен вести на мобильный адрес вида `/m/заказ?table=<подписанный-токен>`.
- [ ] Сервер по токену определяет стол; гость не вводит и не подменяет номер стола.
- [ ] Для мобильной версии сделать отдельный адаптивный интерфейс, а не открывать планшетную вёрстку «как есть».
- [ ] Добавить срок жизни/отзыв QR-токена и возможность перевыпуска в админке.
- [ ] Заказы с телефона создавать в iiko на столе из QR и помечать источником `QR`.
- [ ] Определить сценарий нескольких гостей за одним столом: отдельные заказы или объединение в открытый заказ iiko.

## Не входит в текущий MVP

- Оплата, пречек и фискализация.
- Полное назначение официанта в iiko.
- Мульти-ресторанность и изоляция организаций/арендаторов.
