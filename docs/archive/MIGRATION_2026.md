# Архив: перенос BB Kiosk в GitLab и на новый сервер

- Статус: исторический документ
- Дата архивации: 18 августа 2026 года

Этот файл фиксирует решение первого переноса проекта. Он не является актуальной
инструкцией deploy. Используйте [../DEPLOYMENT.md](../DEPLOYMENT.md). Конкретные IP,
пароли, токены и временное состояние серверов намеренно не сохранены в Git.

## Принятые решения

- канонический репозиторий перенесён в группу GitLab `yoles-rests/bb-kiosk`;
- монорепозиторий сохранён;
- Node.js 22 и PostgreSQL 16+ являются минимальными runtime-версиями;
- web, API, waiter, OTA и bridge собираются одним GitLab pipeline;
- production deploy выполняется вручную;
- секреты приложения хранятся на сервере, deploy/signing secrets — в protected
  GitLab Variables;
- GitHub временно сохраняется как резерв до успешной проверки GitLab Runner.

## Состав переносимых данных

1. PostgreSQL custom dump.
2. `uploads/` с баннерами и изображениями карточек.
3. `ota/` с версиями, уже установленными на устройствах.
4. Server env и Firebase Admin JSON по защищённому каналу.
5. Nginx, systemd units, health и backup timers.
6. TLS/DNS, webhook iiko и публичные QR URL.

## Безопасный cutover

1. Подготовить новый сервер параллельно, не запуская дублирующие фоновые задачи
   iiko.
2. Перенести предварительный dump, uploads и OTA.
3. Проверить API через Host override без создания production-заказа.
4. Остановить запись на старом API.
5. Создать и проверить финальный dump.
6. Восстановить БД, применить миграции и повторно синхронизировать изменяемые
   файлы.
7. Запустить API, проверить readiness, затем переключить DNS и webhook.
8. Проверить заказ, статусы, вызов официанта, push, QR и OTA.
9. Сохранить старый сервер read-only минимум на 72 часа для rollback.

## Rollback

DNS возвращается на старый сервер только после проверки заказов, успевших попасть
на новый. Два сервера не должны одновременно принимать запись и выполнять iiko
background sync.

## После переноса

Ротируются временные GitLab PAT/deploy key, root-доступ, iiko Client Secret и
Firebase Admin service account. `TOKEN_SECRET` и `IIKO_CONFIG_ENCRYPTION_KEY` без
специальной миграции не меняются.
